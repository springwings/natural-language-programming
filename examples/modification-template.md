# 软件修改指令模板

> 用途：软件做出来后，准确告诉 AI「改哪里、改成什么样、别改什么」。
> 对应书中：第14章（核心）、第15、16、17章。

---

## 基本模板（复制填空）

```text
请修改软件，具体要求如下：

【1. 当前的问题】
在哪个页面 / 哪个功能，现在是什么样子，出现了什么问题。
（附上截图更好）

【2. 期望的结果】
修改后应该是什么样子、达到什么效果。

【3. 修改范围】
只修改：______（明确指出页面 / 功能 / 文件）
不要修改：______（明确列出不能动的部分）

【4. 修改前后的行为对比】
修改前：用户做 X，结果是 Y
修改后：用户做 X，结果应该是 Z

【5. 执行方式】
请先告诉我你打算怎么改（修改计划），
我确认后再动手。一次只改这一处，改完告诉我，
并说明如何验证修改成功、以及可能影响到的其他地方。
```

## 填写示例（花店小助手）

```text
请修改软件，具体要求如下：

【1. 当前的问题】
在「订花列表」页面，每行只显示客户名字和电话，
我看不出还有几天要送花，每次都要点进去看日期。见截图。

【2. 期望的结果】
列表每行直接显示「还有 N 天送达」，
如果只剩 1 天或已经过期，用红色加粗显示。

【3. 修改范围】
只修改：订花列表页面
不要修改：新增订花表单、客户管理页面、统计页面、数据结构

【4. 修改前后的行为对比】
修改前：列表显示「王阿姨 / 138xxxx / 5月10日」
修改后：列表显示「王阿姨 / 138xxxx / 5月10日（还有2天）」

【5. 执行方式】
请先告诉我你的修改计划，我确认后再改。
只改这一处。改完告诉我，并说明我需要怎么验证。
```

## 为什么这样写（要点）

1. **不要只说「改一下」**——AI 不知道你说的「改一下」是改哪里、改成什么样。
2. **描述当前问题 + 期望结果**——让 AI 知道起点和终点。
3. **明确修改范围，并列出「不要改」的部分**——这是防止改错地方、影响其他功能的关键。
4. **给出修改前后的具体例子**——比抽象描述准确得多。
5. **先要计划、确认后再改，一次只改一处**——出问题容易定位，也不容易越改越乱。
